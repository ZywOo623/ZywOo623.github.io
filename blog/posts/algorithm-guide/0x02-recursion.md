学 0x02「递推与递归」时，我最初觉得递推比递归顺手。遇到递归代码，我能大致看出它在往下调用，却不太明白为什么子问题做完还要返回、返回之前又为什么有时要 `pop_back()`。

后来我发现，先别急着看函数名。把“这一层正在处理什么”说清楚，代码会容易读很多。

## 状态不一定是排列

我一开始把状态空间想成了所有情况的全排列。拿数字 `1、2` 各自“选或不选”来检查，就能发现答案是 `{}`、`{1}`、`{2}`、`{1,2}` 四种。这里连空集也算，而且 `{1,2}` 不需要再算一个 `{2,1}`。

所以做题时我现在会先问：这题是只在乎**选了哪些**，还是还在乎**选择顺序**？

- 每个数选或不选：$2^n$ 种。
- 从 `n` 个数中恰好选 `m` 个：组合，顺序不重要。
- 把 `n` 个不同的数排成一列：排列，顺序重要。

递推从已知的小状态向大状态算；递归则先处理更小的同类问题，再回到当前这一层。两者都不能省略状态和边界的定义。

## 我卡住的“撤销”到底在做什么

枚举时，如果共用的 `chosen` 原本是 `{1}`，我又放入了 `2`，那它暂时变成 `{1,2}`。这一条分支走完后，必须把 `2` 删除，才能让下一条分支重新从 `{1}` 开始。

```cpp
chosen.push_back(2);  // 做选择
dfs(...);             // 继续处理后面的选择
chosen.pop_back();     // 恢复共用容器
```

`pop_back()` 是**撤销修改**，不是“返回上一层”的指令。当前函数执行完或遇到 `return`，才是返回；上一层会接着执行它尚未完成的代码。

这也解释了为什么递归函数不只是把一段代码挪到 `main` 外：每次调用都有自己的参数和返回位置。像 `angle + a[i]` 这样按值传入的新角度，不会修改上一层的角度；但共用数组或容器被改过，就要考虑撤销。

## 第一行为什么有 32 种，而不是整张表都乱试

书里的“费解的开关”给我印象很深。$5\times5$ 个位置看起来有很多按法，但只需自由尝试第一行的 $2^5=32$ 种。

原因是第一行决定后，它哪里还亮着，就必须按第二行对应列的按钮；第二行的状态又决定第三行，依次向下。走到最后仍要检查末行是不是全灭。

我后来做 [CF275A](https://codeforces.com/problemset/problem/275/A) 时也碰到类似的灯，但那题直接给了每个按钮按了多少次，只用计算最终状态。“按钮影响自己和四邻”只是共同规则，**要找操作**和**已知操作求结果**是不同任务。

## 从枚举到代码：CF550B 的 `mask`

[CF550B](https://codeforces.com/problemset/problem/550/B) 是我的一次“思路和代码对上”的练习。`n≤15`，可以用二进制表示选题方案。我一开始明白某一位是 `1` 表示选，却不明白外层为什么还要循环 `mask`。

以三道题为例：

```text
mask = 1 = 001₂ → 只选第 1 题
mask = 2 = 010₂ → 只选第 2 题
mask = 5 = 101₂ → 选第 1、3 题
```

也就是说，外层每循环一次，换一整套方案；内层才逐题读取这一套方案的 0 和 1。核心代码是：

```cpp
for (int mask = 1; mask < (1 << n); ++mask) {
    int cnt = 0, sum = 0;
    int mn = INT_MAX, mx = INT_MIN;

    for (int i = 1; i <= n; ++i) {
        if (mask & (1 << (i - 1))) {
            ++cnt;
            sum += c[i];
            mn = min(mn, c[i]);
            mx = max(mx, c[i]);
        }
    }

    if (cnt >= 2 && l <= sum && sum <= r && mx - mn >= x) {
        ++ans;
    }
}
```

这是我在学习中补全的代码，题面样例检查通过；目前还不能写成“已在 Codeforces AC”。

## 这一节后半段，我想先抓住主线

四柱汉诺塔的递推式来自“选一个分割位置，算这一种搬法的步数，再取最小值”。分治求等比数列和，是把长和拆成短和，不在取模之后随便做除法。分形街道先判断房屋位于哪一块，再求块内编号和坐标，最后根据那一块的位置做坐标变换。

其中分形街道我还需要画图多练，不能说已经熟练。相比记住所有坐标公式，这次对我更重要的收获是：遇到大问题时，先找到**更小的同类问题**，再想子问题的答案如何变成原问题的答案。

我也把下一步留得具体一些：不看参考代码重写 [CF189A](https://codeforces.com/problemset/problem/189/A) 的递推，尝试自己写出 [CF1097B](https://codeforces.com/problemset/problem/1097/B) 的递归版本。学完一节不代表每种写法都已经熟练，但至少我现在知道卡住时应该先检查“状态、边界、转移或分支、返回后的现场”这几件事。
