学习《算法竞赛进阶指南》的位运算这一节时，我最初以为难点主要是记住 `&`、`|`、`^` 这些符号。真正往下学才发现，我更容易卡在“一个变量现在代表什么”上：快速幂里的 `ans` 是什么？二进制位为 `0` 时到底跳过了什么？题目要求取模，为什么不能最后再取？

这篇文章记录我目前对 0x01 位运算的理解，也保留做题时尚未完全解决的问题。教材知识与我后来做的 CF 练习会分开写。

## 从右往左看二进制

二进制最低位是第 `0` 位。以 `13` 为例：

```text
13 = 1101₂
     3210  ← 位号
```

因此 `13 = 8 + 4 + 1`，第 `0`、`2`、`3` 位为 `1`。位运算是在对应的位上操作：

```cpp
(n >> k) & 1       // 读第 k 位，得到 0 或 1
n | (1 << k)       // 把第 k 位设为 1
n & ~(1 << k)      // 把第 k 位清为 0
n ^ (1 << k)       // 翻转第 k 位
```

对我来说，“位号从 `0` 开始”看着很简单，手算状态时却真能数错。后来检查状态压缩题时，我就曾把 `0101₂` 中为 `1` 的位看错；正确的是第 `0` 位和第 `2` 位。

还有一个容易混的地方：`n & 1` 检查最低位，可用来判断奇偶；`n & (1 << k)` 检查第 `k` 位时，得到的非零结果通常是 `2^k`，不一定是 `1`。

## 我是怎么理解快速幂里的 `ans` 的

快速幂要解决的是指数很大时，如何少做乘法。因为指数可以拆成二进制，例如：

$$
6=(110)_2=4+2,\qquad 5^6=5^4\cdot5^2.
$$

以前我说过类似“2 的平方和 2 的一次方相乘”的话，回头看，这样说很容易把底数和指数混在一起。更清楚的说法是：**`6` 决定选择指数为 `4` 和 `2` 的两项；原来的底数仍然是 `5`。**

代码从指数的最低位往高位走。当前候选幂依次是 `a、a²、a⁴、a⁸……`：

```cpp
long long power(long long a, long long b, long long p) {
    long long ans = 1 % p;
    a %= p;

    while (b > 0) {
        if (b & 1) ans = ans * a % p;
        a = a * a % p;
        b >>= 1;
    }
    return ans;
}
```

我现在把三个变量分开看：

- `b`：还有哪些指数位没处理；
- `a`：当前位对应的幂，每轮平方后准备下一位；
- `ans`：已经选中的那些幂的乘积。

当前位是 `0`，只是不把这一轮的 `a` 乘进 `ans`，**不是把 `a` 变成 `0`**。`ans` 从 `1` 开始，因为它做的是累乘。

我还问过右移 `b` 和平方 `a` 能不能换顺序。关键并不是死记某一种排版，而是**先用当前位和当前的 `a` 更新 `ans`**；完成这一轮后，才能准备下一位。

## 取模和累加不是一回事

`a^b mod p` 的目标就是求余数，`p` 是题目给的，不能自己随意换。边计算边取模，得到的最终余数不变，也不用先存下巨大的完整幂。

我曾把“快速幂相当于累乘，取模是累加吗”放在一起问。现在需要拆开：

- 快速幂选中二进制位对应的幂，做的是**累乘**；
- `mod p` 只是**求余数**；
- 教材后面为避免大整数相乘溢出，介绍的“倍增求乘法取模”才会按二进制位**累加**。

同样叫 `ans`，快速幂从 `1` 开始，倍增乘法从 `0` 开始，因为一个累计乘积，一个累计和。

快速幂的时间复杂度是 $O(\log b)$，并不会扩大 `long long` 的容量。不要求取模时可以删去 `% p`，但必须保证每一步乘法和最终结果都装得下；例如不能因为乘法次数少，就认为 `long long` 能精确存下 $2^{100}$。

> 代码范围说明：上面的简洁快速幂要求取模前的两个数相乘仍不超过 `long long`。书中还专门讨论了 `a、b、p` 可达 $10^{18}$ 时的乘法取模，不能把上面的代码直接用于那种范围。

## 一个位也可以代表一个“是否经过”

书中的状态压缩让我看到位运算不只是处理数字，还能表示一个集合。比如某个整数的第 `j` 位是 `1`，就表示第 `j` 个点已经经过。

最短 Hamilton 路径例题里的 `f[S][j]`，我现在会读成：

> 从起点出发，恰好经过集合 `S` 中的点，目前停在 `j`，此时的最短路径长度。

`S` 是经过了哪些点，`j` 是现在在哪个点，`f[S][j]` 才是要求的长度。我之前回答这类问题时，容易只说出变量是什么，却没有把**整个状态代表的值**说完整。

书中的“起床困难综合症”还展示了另一种思路：`AND`、`OR`、`XOR` 在各位上独立作用，可以逐位考虑。这里不能随便换成普通加法，因为加法会产生进位，让不同位互相影响。

## `lowbit` 留下了哪一位？

对正整数 `n`，`n & -n` 会只留下最低位的 `1`：

```text
22       = 10110₂
22 & -22 = 00010₂ = 2
```

结果 `2` 是这一位对应的**数值**，不是位号。每次从 `n` 中减去 `n & -n`，就会删除一个 `1`，直到 `n` 变成 `0`。

```cpp
while (n > 0) {
    int bit = n & -n;
    // 处理这个最低位的 1
    n -= bit;
}
```

这段循环运行多少次，原数的二进制中就有多少个 `1`。

## 做题时，我仍需要练“从思路到代码”

这一节后，我尝试了几道教材外的 Codeforces 题。它们目前是**学习与代码练习记录，不是已独立 AC 的题单**。

[CF1514B](https://codeforces.com/problemset/problem/1514/B) 让我发现：即使知道要用快速幂，也必须先从题意推出为什么答案是 $n^k$。[CF1362B](https://codeforces.com/problemset/problem/1362/B) 则让我意识到，不熟悉 `set` 不一定会卡死整题，用 `vector` 和存在标记也能验证异或后的集合。

在 [CF1095C](https://codeforces.com/problemset/problem/1095/C) 中，我已经能手算 `13 = 1 + 4 + 8`，再拆成 `1 + 2 + 2 + 4 + 4`，但第一次写代码时直接把原始 `n` 右移成了 `0`，后续判断自然出错。这类问题不是再背一遍 `n & 1` 就能解决的，而是要继续练习：哪些变量必须保留原值、先判断什么、最后要输出什么。

## 这节课给我留下的检查清单

以后碰到位运算题，我会先问自己：

1. 当前处理的是第几位？位号是不是从右往左数？
2. 这个变量保存的是位号、位对应的数值，还是一个集合状态？
3. 快速幂中，指数的当前位是否为 `1`？当前 `a` 又是哪一次幂？
4. 取模之前的中间运算会不会溢出？
5. 我只是推导出了答案，还是已经把构造、循环和输出完整写出来了？
